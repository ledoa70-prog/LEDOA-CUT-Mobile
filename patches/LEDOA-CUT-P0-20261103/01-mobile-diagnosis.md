# 보고 1 — 모바일 진단

문서: LEDOA-CUT-P0-20261103-REV1 / 담당: 개발실 Sol 6.1

## 실제 제공 자료

제공된 약 13초 화면 녹화에서 모바일 v0.8.11, 2개 클립, 총 43.0초 프로젝트를 확인했다. 재생이 27.5초 경계에 도달한 후 시간 표시와 미리보기가 진행하지 않고 재생 중 아이콘이 유지된다. 이 녹화만으로 Android 프로세스 종료나 최초 하드웨어 디코더 오류를 확정할 수 없다.

첨부 파일의 H.264 / 1080×1258 / 가변 FPS는 **화면 녹화 형식**이다. 편집 원본의 코덱·FPS·해상도로 간주하지 않았다. 후속으로 실제 두 원본 영상이 제공되어 별도 분석했다. 두 파일 모두 HEVC Main / 1080×1920 / 약 30fps / AAC 48kHz 스테레오이며, FFmpeg 전체 디코딩은 오류 없이 끝났다. 두 번째 파일은 프레임 간격과 명목 FPS가 일정하지 않다. 원본 컨테이너 길이는 각각 약 29.056초·15.509초다. 자동 저장 프로젝트와 실제 기기 logcat은 아직 제공되지 않았다. 자세한 메타데이터·해시는 `evidence/original-media-summary.json`에 있다.

## 수정 전 재현과 코드 위치

| 확인한 오류 | 조건과 증거 | 기준 v0.8.11 위치 |
|---|---|---|
| 복구가 같은 디코더 재로드에 갇힘 | 다음 요소의 재생을 멈추는 시험에서 약 2.7초 간격으로 재로드. 프레임 카운터가 41→23, 37→0 등으로 감소해도 `count !== previous`가 진전으로 판정. 10초 이상 같은 요소·같은 프로젝트 시각 유지 | `assets/app.js` `installPlaybackV065/checkProgress` (약 3475행) |
| 지난 클립 소스가 준비 타이머에서 부활 | 10개 짧은 클립을 재생하면 활성 클립 2번에서 소스가 0·1·2번에 붙음. 호출 스택은 `timer → drawableVideo → ensureRuntime → attachSourceIfNeeded → load` | `installFirstFrameAndTimelineTrimV0513`, 약 2460·2497행 |
| 이전 시작 콜백이 새 재생을 되감음 | metadata 완료를 지연한 뒤 시작 취소·1초 탐색·재생 후 이전 콜백을 전달하면 영상 시각이 약 1.301초→0초, 프로젝트 시각은 약 1.293초 유지 | `installReliablePlayButtonV0514/warmThenStart`, 약 2696행 |

디코더 멈춤과 이벤트 지연은 경합을 검사하기 위해 **시험에서 주입한 조건**이다. 이것을 대표 휴대폰에서 수집한 하드웨어 오류 로그라고 주장하지 않는다. 준비 타이머의 소스 재부착은 일반 연속 재생에서도 재현했다.

증거: `evidence/decoder-fault-before.json`, `budget-before.json`, `stale-start-before.json` 및 재현 스크립트.

## 수정 대상·위험

재생 진전 판정, 준비 작업의 수명과 소유권, 이전 세션 콜백 차단만 우선 수정한다. 프레임 준비를 취소하는 조건이 엄격해져 정상 시작이나 탐색을 방해할 수 있으므로 반복 전환·탐색·다시 재생과 저장/복원을 회귀 검사한다. 기존 복구 대기시간을 늘리지 않는다.

Android의 최초 디코더 정지, 메모리 압박/OOM, WebView 프로세스 종료 여부는 미확정이다. 제공 원본을 이용한 Android 재생 검증과 실제 기기 로그가 필요한 후속 진단으로 남긴다.
