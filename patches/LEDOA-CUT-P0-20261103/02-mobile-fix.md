# 보고 2 — 모바일 긴급 수정

담당: 개발실 Sol 6.1 / 신규 후보: v0.8.12-p0-candidate

## 수정 파일

`assets/app.js`

- 카운터 감소·재로드·탐색을 진행으로 세지 않고, 실제 앞으로 움직인 디코딩을 확인한다. 복구 중에는 요청한 위치를 지난 진전이 있어야 기한을 갱신한다.
- 기존 복구 단계는 유지한다. 같은 요소 재로드에서 회복하지 못하면 4.2초 단계의 새 요소 교체에 도달한다. 계속 실패하면 8.5초 단계에서 중지한다.
- 준비 여부 조회에서 `ensureRuntime`을 호출하지 않는다. 이전 클립·이전 위치·교체된 요소·재생/출력 중인 상태의 준비 콜백을 취소하고 이벤트/타이머를 정리한다.
- 시작 및 복구의 늦은 metadata 콜백에서 토큰·요소 소유권·현재 세션을 확인한다.
- 최대 96개 진단 기록을 메모리에만 보관한다. 파일명·URL·미디어 본문을 기록하지 않는다. `LedoaPlaybackDiagnostics.snapshot()`으로 확인할 수 있다.

`assets/index.html`, `assets/sw.js`

- 버전 표시와 자산 캐시 이름만 v0.8.12로 변경했다.

## 수정 전후

| 시험 | 수정 전 | 수정 후 |
|---|---|---|
| 다음 디코더가 멈춘 조건 | 재로드 반복, 같은 요소·경계 시각에 고정 | 한 번 재로드 후 한 번 교체, 실제 재생 종료까지 완료 |
| 교체 후에도 계속 고장 | 복구 진행 오인으로 무한 반복 가능 | 정해진 단계 후 중지, 클립 데이터 유지 |
| 늦게 도착한 폐기 요소/이전 복구 세션 콜백 | 소유권 검사 불충분 | 요소 부활·이전 위치 탐색 차단 |
| 준비 타이머의 과거 클립 재부착 | 활성 소스 최대 3개 | 최대 2개, 해당 재부착 호출 0개 |
| 취소된 시작의 metadata 콜백 | 약 1.301초→0초 되감기 | 약 1.301초 유지 |
| 10개 합성 영상 반복 | 복구 조건과 자원 검증 추가 필요 | 108회 전환·100회 탐색/시작/취소 통과, JS 오류 0개 |
| 자막·이미지·MT-135·BGM·디졸브 | 기존 경로 | 대표 경로 재생 통과 |
| 구버전 프로젝트 호환 | v0.8.11에서 생성 | 수정본 저장/재열기 및 v0.8.11 재열기 후 메타데이터·미디어 해시 일치 |

소스가 붙은 `<video>` 요소 수는 하드웨어 디코더 수의 대용 지표다. Android 실제 할당 수나 메모리 누수를 계측한 결과는 아니다.

## 기능·데이터 보호

자막·자동 인식·모자이크·타이포 렌더러·폰트 등 수정 대상 외 소스 27개를 그대로 유지했다. 저장 DB `ledoa-cut-mobile-v1` / 버전 1 / `project`·`media` 저장소 및 `latest` 키를 바꾸지 않았다. 프로젝트 버전 512, 미디어 키, 저장/복원 함수도 변경하지 않았다.

전체 기능이 Android에서 검증됐다는 뜻은 아니다. MP4 품질 게이트와 실제 기기 항목은 다음 보고에서 미통과/미검증으로 남긴다.
