# 보고 3 — 모바일 배포 검증 / 배포 보류

담당: 개발실 Sol 6.1 / 판단: **정식 완료 및 설치용 APK 전달 보류**

## 기존 작업물 보호

v0.8.11 배포 APK와 소스 ZIP은 변경하지 않고 보존했다. 해시는 `baseline.json` 및 `evidence/baseline-integrity.json`에 있다. 실제 휴대폰에는 접근하지 않았으므로 대표의 자동 저장 프로젝트·원본 영상·오디오 백업을 완료했다고 주장하지 않는다. 사용자의 앱 삭제·저장공간 초기화·프로젝트 삭제를 수행하거나 요구하지 않았다.

## 시험 환경

- Linux x86_64, Chromium 133.0.6943.0, Playwright.
- 기존 회귀는 합성 H.264 720×1280 30fps + 48kHz AAC 영상으로 수행했다. 이후 받은 실제 원본은 HEVC Main 1080×1920 약 30fps + AAC 48kHz 스테레오로 확인했다. 데스크톱 시험 Chromium은 HEVC 재생을 지원하지 않아 기존 회귀 통과를 원본 HEVC 통과로 해석하지 않는다.
- 소프트웨어 렌더링/인코딩. Android 하드웨어 디코더 및 MediaStore 시험 아님.
- 브라우저의 별도 임시 문맥에서 v0.8.11 DB를 만들고 수정본/구버전으로 왕복했다. 실제 휴대폰의 DB를 열거나 수정하지 않았다.

`mobile-p0-regression.json`은 `previewPassed: true`, `passed: false`, `releaseReady: false`이며 시험 프로세스는 종료 코드 1을 반환했다. MP4 생성만으로 합격 판정하지 않았다. 추가 프레임 요청만으로도 출력 문제가 해소되지 않아, 그 실험은 제품 코드에 넣지 않았다. 출력 엔진은 v0.8.11과 동일하다. 이 Linux 결과를 Android에서도 같은 고장이 난다고 단정하지 않으며, 그렇다고 Android 출력 검증을 통과로 바꾸지도 않는다.

## 미배포 후보의 정적 검증

| 후보 | 패키지 | versionCode | 변경 범위 |
|---|---|---:|---|
| 0.8.12-p0-candidate | kr.ledoa.cut.captionbeta | 812 | manifest + app.js/index.html/sw.js |
| 0.8.11-rollback-813 | 동일 | 813 | manifest만 변경, 앱 코드는 v0.8.11 |

두 후보 모두 기존 인증서 SHA-256 `bd7dad9ddae23ee1086bdbf5d0b578f45348036456deab7363b75dddd86bf9e8`와 일치한다. 수정 후보는 나머지 495개 항목, 복구 후보는 나머지 498개 항목의 압축 데이터 SHA-256이 원본과 일치한다. 모델·네이티브 라이브러리·classes는 유지했다. 16KB 네이티브 정렬 및 ZIP CRC도 검사했다. 후보 해시/크기는 검증 JSON에 기록했다.

서명·패키지 일치는 실제 설치/데이터 유지 검증의 대체가 아니다. APK는 검토용 내부 산출물로 두고 이번 PR에 업로드하거나 설치 링크로 배포하지 않았다.

## 안전한 현장 검증 및 복구 순서

1. 실제 기기에서 현재 자동 저장 프로젝트와 원본 미디어를 먼저 별도로 보존하고, 복원 가능성을 확인한다.
2. 같은 원본 형식으로 27.5초 전환, 반복 탐색/중지/재생을 재현하고 Android/WebView/MediaCodec 로그를 수집한다.
3. 승인된 현장 검증에서 같은 패키지·같은 서명의 후보를 덮어 설치한다. 앱 제거·데이터 초기화를 전제로 진행하지 않는다.
4. 현재 프로젝트 열기→연속 재생→저장/재열기→MP4 출력→갤러리에서 전체 재생을 확인한다. 영상 길이·실제 프레임 진전·음성 종료·싱크를 대조한다.
5. 문제가 있으면 현재 프로젝트를 보존하고 같은 서명의 복구 후보(code813)로 엔진만 되돌린다. 일반 설치에서 낮은 code811 원본으로 바로 내리라고 안내하지 않는다. 복구 설치 자체도 실기기 확인이 필요하다.

복구 후보를 사용한 뒤의 후속 배포는 versionCode 813보다 높아야 한다. 실제 프로젝트 백업과 위 설치 검증 전에는 배포 승인으로 처리하지 않는다.

## 후속 사용자 지시 — 개발 종료 및 긴급 후보 전달

사용자가 추가로 “작업 종료하고 패치 줘, 우선 편집 완료 해야돼”라고 지시했다. 이에 추가 개발·시험을 종료하고 기존에 생성한 v0.8.12-p0-candidate와 같은 인증서의 v0.8.11-rollback-813을 제공한다. 위 게이트 결과는 변경하지 않으며 정식 안정화 완료로 기록하지 않는다. Android 설치·현재 프로젝트·native MP4 출력은 계속 미검증이다. 기존 앱 삭제나 저장공간 초기화를 지시하지 않는다.
