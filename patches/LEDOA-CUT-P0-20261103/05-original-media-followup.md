# 후속 보고 — 제공 원본 분석 / Android 실행 검증 차단

담당: (주) 레도아 개발실 Sol 6.1

## 이번에 확인한 자료

화면 녹화와 별도로 원본 MP4 두 개가 추가 제공되었다. 원본 파일은 변경하지 않았다. 공개 저장소에는 영상·프레임 이미지·프로젝트 본문을 올리지 않고 메타데이터와 해시만 기록한다.

| 자료 | 첫 번째 원본 | 두 번째 원본 |
|---|---:|---:|
| 파일 | 1000067125.mp4 | 1000067126.mp4 |
| 크기 | 47,094,386 bytes | 25,361,067 bytes |
| 영상 | HEVC Main / hvc1 / 1080×1920 / 8-bit | 동일 |
| 평균 FPS | 약 30.01 | 약 29.92 |
| 컨테이너 길이 | 29.055542초 | 15.509083초 |
| 음성 | AAC LC / 48kHz / 스테레오 | 동일 |
| FFmpeg 전체 디코딩 | 오류 없이 종료 | 오류 없이 종료 |

두 번째 원본의 명목 프레임레이트는 60000/1001이지만 실제 프레임 간격은 주로 약 33.44ms이고 47.6ms 간격도 있다. 명목 60fps를 실제 고정 60fps로 간주하지 않는다. 두 파일의 마지막 패킷 일부에 discard 표시가 있으므로 컨테이너 프레임 수와 실제 디코딩 수의 차이를 곧바로 손상으로 판정하지 않는다.

FFprobe에 표시된 HEVC level 값은 둘 다 30이다. 이 메타데이터만으로 휴대폰의 최초 디코더 정지 원인을 확정하지 않았고, 비트스트림 패치·재인코딩·원본 교체를 제품에 추가하지 않았다.

증거: `evidence/original-media-summary.json`. 전체 디코딩 검사에는 FFmpeg 6.1.1을 사용했다. Linux 디코딩 성공은 Android MediaCodec 성공의 대체가 아니다.

## 프로젝트 재현 범위

화면 녹화는 총 43.0초 프로젝트의 약 27.5초 전환 정지를 보여준다. 첫 원본은 약 29.1초여서 실제 편집 프로젝트에는 트리밍이 있을 수 있다. 자동 저장 프로젝트가 제공되지 않았으므로 정확한 시작/종료 트림·오버레이·BGM 설정을 확보했다고 주장하지 않는다.

후속 Android 시험 스크립트는 첫 원본을 27.5초에서 자른 경우와 끝까지 사용하면서 앞부분을 잘라 27.5초를 만든 경우를 구분한다. 이들은 재구성 시험이며 대표의 실제 프로젝트가 아니다.

## Android 시도와 중단 근거

Android 16 / API 36 기본 x86_64 이미지, Emulator 37.2.13, SwiftShader, KVM 없음으로 별도 가상 장치를 준비했다. ADB 연결과 셸 응답까지 확인했지만, 약 15분의 최종 초기 기동에서도 `sys.boot_completed`가 비어 있었다. 이 시도를 중단하고 가상 장치를 종료했다.

- **APK 설치·실행: 미실행**
- **제공 HEVC 원본의 Android 클립 전환: 미실행**
- **APK 덮어 설치에 따른 프로젝트 유지·복구: 미실행**
- **Android MediaRecorder / MediaStore MP4 출력: 미실행**

이것은 시험 환경 초기화의 한계이며 LEDOA CUT 앱 실행 실패나 원본 HEVC 실패로 집계하지 않는다. `evidence/native-attempt.json`에 중단 당시 커널 로그 일부와 명시적인 미실행 상태를 보존했다. 준비한 `tests/native/` 코드는 구문 검사와 계측 APK 컴파일까지만 확인했다. Android 전체 시험을 통과한 코드로 표시하지 않는다.

## 배포 판단과 다음 검증

추가 원본 분석으로 확인되지 않은 원인을 추측해 제품 코드를 더 바꾸거나 후보 버전을 올리지 않았다. 기존 3개 재생 제어 수정과 브라우저 회귀 결과를 유지한다. 제공 HEVC·실제 프로젝트·최종 MP4의 Android 검증은 남아 있다.

검증 게이트상 정식 완료는 보류다. 이후 사용자가 “작업 종료하고 패치 줘, 우선 편집 완료 해야돼”라고 지시하여 개발·추가 시험을 종료하고 현재 v0.8.12 후보 및 동일 서명 code813 복구 후보를 제공한다. 미검증 사실을 그대로 알리며, 새 패치 버전을 만들거나 실기기/출력 시험 통과로 바꾸지 않는다. 아래 항목은 실행한 결과가 아니라 아직 남아 있는 검증 목록이다.

1. 현재 프로젝트와 원본 미디어를 보존하고 복원 가능성을 확인한다.
2. 기준 v0.8.11에서 전환 정지와 MediaCodec/WebView 로그를 수집한다.
3. 동일 서명 후보의 덮어 설치, 프로젝트 열기·저장·재열기를 검증한다.
4. 원본 HEVC 전환·탐색·기존 오버레이 재생과 MP4 전체 출력·재생을 검증한다.
5. 같은 서명의 상위 versionCode 복구본으로 데이터 유지까지 확인한다.

실제 휴대폰 데이터에 접근하거나 앱 삭제·초기화를 수행하지 않았다. 모바일 정상화가 검증되지 않았으므로 PC 안정화는 시작하지 않았다.
